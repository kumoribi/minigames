## 1. 文書の読み方と目的

投資を通じて資金を増やし、有限の人生の中で幸福を購入するカード型ボードゲーム。資産最大化ではなく、幸福ポイント最多を目指す。早期の幸福購入と投資資金の確保の判断を中心に置く。

- 【確定】は依頼文および会話で承認されたルール。
- 【仮値】は試作・比較検証用の数値。ルール方式の承認と数値バランスの確定は区別する。
- 【提案】は未承認の詳細案。実装上の既定値として黙って採用しない。
- 【未決定 U-xx】は実装前または該当段階前に解決する事項。

元の「固定基礎点＋株枚数」「任意の銀行不動産売却」「利息切り上げ」「0.1万円単位」は後の修正で廃止。以降は本書の修正後ルールを使う。

## 3. 基本形式と勝利

【確定】標準は人間1人＋対戦AI1人。対戦AIはプレイヤーと同じ現金・資産・行動制限を持ち、幸福による勝利を目指す。市場NPCはイベントによる株・幸福の価格形成だけに参加し、個別の資金管理や勝利点を持たない。

【確定】24ラウンド。全員が1手番ずつ行動すると1ラウンドが終了。先手はラウンドごとに巡回する。人生の経過を年齢で示す。終了時に幸福最多が勝利。同点は共同勝利で、資産額を追加の勝敗基準にしない。

【確定】対人は同じ端末を交代して使う。オンライン対戦は初版対象外。

【仮値】共通エンジンは2～4人を想定。目標時間15～25分。

【提案】ラウンド1を22～24歳、ラウンド24を68～70歳と表示し、70歳で終了する。具体的な年齢表示はU-08。

## 4. 金額と初期構成

【確定】金額の単位は万円。金額は整数で保持し、割合計算で生じる1万円未満の端数は切り捨てる。利息、不動産売却額にも適用する。画面に小数の金額を表示しない。

割合は整数比率で扱い、例として売却額はfloor(購入額×(100＋変動率)/100)、利息はfloor(元本×金利率/100)。率は符号付き整数％を候補とし、負の売却額を作る率は採用しない。

| 項目 | 仮値・候補 |
|---|---|
| 初期現金 | 各60万円 |
| 基礎収入 | 各4万円／ラウンド |
| 会社 | 3社、基礎点相当のNPC株6／10／14枚 |
| 追加の初期NPC株 | 各社2枚候補。採用時の初期株価は8／12／16万円 |
| 不動産 | 3件、購入40／50／60万円、家賃4／5／6万円、初期入居中 |
| 通常融資 | 元本20万円、金利5%／ラウンド、未契約2枚 |
| 緊急融資 | 元本10万円、金利10%／ラウンド、取得後補充 |
| プレイヤー貸付 | 各人に提案1枠、元本20万円、金利5%候補 |
| 幸福 | 基礎価格10万円、初期購入済み0枚 |
| イベント | 24枚、ラウンド開始時に1枚 |
| 借入制限 | 最大50万円・最大2契約・担保評価50%以下の全条件 |

基礎点相当NPC株を置く場合、同額の固定基礎点をさらに足さない。追加NPC株の有無はU-06。元本10万円・金利5%なら利息は0万円となる。端数処理は変えず、通常のカード構成でゼロ利息が意図せず発生しない元本・率を選ぶ。

## 5. 株式市場

### 5.1 価格と所有権

【確定】会社の基礎点相当もNPCの購入カードで表す。

現在株価（万円）＝その会社に現在積まれている株カード総枚数。

当初の基礎点を恒久的な下限として使わない。プレイヤー・対戦AI・NPCの株は価格形成に等しく1枚として数える。1枚につき1万円。

【確定】購入時は1枚追加した後の株価を支払う。売却時は選択した1枚を除去した後の株価を受け取る。途中の自分のカードも売却できる。他人のカードは売れない。取得原価は購入時に固定し、他カードの売買で変更しない。

例: 10枚なら現在10万円。購入は11万円、直後の売却は10万円。NPC株10枚＋プレイヤー株3枚からNPC株5枚を除くと、13万円から8万円へ下がる。

【確定】0枚なら株価0万円。次の購入は追加後価格1万円。唯一のカードの売却手取りは0万円。操作前に明示する。

売却後は配列位置だけを詰め、残存カードのID・所有者・取得原価を維持する。画面上の「上に積まれた枚数」は需要の履歴の目安であり、売却後の正確な損益とは区別する。

売却見込損益＝除去後価格－対象カードの取得原価。全保有株の処分評価は、その枚数を順次売った価格の合計。全枚数に現在株価を掛けて過大評価しない。

### 5.2 複数増減

通常の主行動は1枚。イベントや資産整理で複数枚を動かす場合は、1枚ずつ価格を更新し、全処理を1トランザクションとして確定する。NPC除去はNPC所有だけを対象とし、足りなければ存在する枚数まで。プレイヤー所有株をイベントで消さない。

【提案】NPC除去順は購入順の古いものから。正確な決定順はU-07。イベントは通常売買の資金移動を伴わず、NPCの財布は作らない。

## 6. 幸福

【確定】共通市場で購入する。現在価格＝幸福の基礎価格＋購入済み幸福カード総枚数。プレイヤーは現在価格を支払い、1枚を追加し1ポイント獲得する。株式とは価格確定タイミングが異なる。

幸福は売却・消去不可、価格下落なし。NPC購入分も価格に算入し永久に残るが、プレイヤーの得点にはしない。基礎価格10万円、購入済み3枚なら、次は13万円。その後14万円となる。NPCが4枚購入すると、現在価格は4万円上昇する。

【確定】幸福購入は主行動1回。購入後の保守的純資産から次回利息を引いた額が0以上必要。幸福そのものを担保・換金可能資産として数えない。

純資産条件の詳細は融資節およびU-02を参照。得点の真実の情報源は所有する幸福カードで、別の得点値を独立加算して二重管理しない。

## 7. 不動産

【確定】各物件の所有者は1人だけ。購入は主行動1回。入居中のみラウンド末に家賃を受け取る。購入価格・家賃・入居状態・所有者を表示する。

【確定】任意売却は不可。不動産売却イベントを引いた本人だけが、所有物件1件を任意で売却できる。主行動は消費せず、その場限り。所有物件なしは不発。見送っても権利は持ち越さない。

売却額＝floor(その所有者が実際に支払った購入額×(100＋イベント変動率)/100)。例: 50万円の物件、＋15%なら57万円、－15%なら42万円。変動率の種類・配分は仮値で未決定。

【確定】売却後は市場へ戻し、元の販売価格で再販売。入居状態は維持する。新たな購入で新所有者の取得価格を記録する。

【確定】売却機会が保証されないため、通常の借入担保や資金繰りの換金可能資産に不動産を算入しない。

【未決定 U-01】資産整理・最終精算でもイベントなしの強制売却を禁止するか、例外として認めるか。通常の80%売却案を復活させない。推奨案はイベント限定を一貫させ、強制売却をしない方式。ただし資産整理中の家賃を残債返済へ充てる。不動産保有で借金を踏み倒す戦略が成立しないか要検証。

## 8. 融資・貸付・借り換え

### 8.1 契約

【確定】銀行借入では元本を一括受領し、完済まで毎ラウンド利息を支払う。プレイヤー間貸付では貸し手の現金を借り手へ移し、利息・元本を貸し手へ返す。銀行は別の固定相手IDで表す。

金融操作は各手番1回。借入・全額返済・借り換え・貸付提案・貸付受諾のいずれか。主行動の前後どちらでも可能。部分返済は初版対象外。救済時の操作はU-03。

貸付提案時は貸し手の元本を確保して二重使用を防止する。借り手が自分の金融操作として受諾した時に契約・送金成立。未受諾提案から利息は発生しない。提案期限・返却はU-04。

### 8.2 制限・評価

【確定】全貸し手合算の借入元本・契約数・担保条件に上限を設ける。緊急カードが常に補充されても上限外では借りられない。担保には株式の保守的な処分評価を使い、幸福・不動産・貸付債権は含めない。

【未決定 U-02】現金を担保へ含めるか、借入金由来の現金をどう除くか。現金をそのまま担保にして借入枠を自己増殖させない。推奨は借入担保を保有株式の処分評価だけに限定し、幸福購入の純資産条件には購入後現金を含める方式。

候補式: 幸福購入後現金＋保有株の処分評価－全借入元本－未払債務－次回利息合計 >= 0。不動産・幸福・貸付債権は除外。カード金利ごとの切り捨て後に利息を合計する。最終ラウンドでも当該末尾の利息を考慮する。

### 8.3 精算

【確定】契約成立ラウンドの末尾から利息発生。毎契約ごとにfloor(元本×金利率/100)。最終ラウンドも対象。元本全額返済済みの契約には以後の利息を課さない。

【確定】借り換えは新元本を旧貸し手へ直接充当し、借り手が一瞬だけ両方の元本を自由使用できないようにする。失敗時は契約・現金をすべて維持。一時的な二重契約ではなく完了後の残高で上限判定する。差額の扱い・同ラウンド金利はU-05。

精算開始時の契約一覧と支払可能額を固定し、未収利息を現金として扱わない。同じ精算で受領予定の利息を、別の利息の支払い原資に先取りしない。実際の入金後は次の操作から使用可能。

### 8.4 支払不足と資産整理

【確定】基礎収入・家賃を受領後、利息を精算する。不足時は救済画面を表示し、資産売却または上限内の緊急借入で解消を試みる。解消不能なら資産整理状態へ。無限に追加借入させない。

【確定】幸福を没収せず、プレイヤーも脱落させない。処分可能な投資資産を処分し、未払いは無利息の残債として維持する。以後の収入を残債返済に充て、完済まで新規借入・幸福購入を禁止。債権者は同順位で按分する。

【未決定 U-03】緊急借入回数、強制処分順、元契約の未払い元本・利息を残債へ移す時点、按分の整数余り、復帰時点。利息だけ残債化して元本を消すことや同じ債務を二重登録することは禁止。推奨は全既存契約を閉鎖して元本＋未払利息を残債へ一度だけ移す方式。端数按分の残額は確定順で1万円ずつ配分する案だが、順序は要承認。

【確定】最終精算では追加の幸福購入は行わない。最終債務処分と未完済者の表示はU-01・U-03の確定後に具体化する。幸福最多という勝利条件や共同勝利は変えない。

## 10. 進行状態と行動

【確定】開始時は開始待ち。ガイドを確認し開始するまでAIや市場は進まない。手番には主行動1回と金融操作1回がある。主行動は株1枚購入・株1枚売却・不動産1件購入・幸福1枚購入・パス。任意の不動産売却は含めない。

開始待ち → ラウンド開始 → イベント公開 → 必要ならイベント選択 → 各人の手番 → 基礎収入・家賃 → 利息と救済・資産整理 → ラウンド確定・保存 → 先手交代 → 次ラウンド。

24ラウンド終了時は最終精算 → 結果。主行動後も明示的なターン終了を待つ。未使用枠は終了時に放棄し、持ち越さない。パスと未行動終了の確認表示はUIで統一する。先手巡回は全員に均等に行い、開始時の先手決定はU-08。

非表示タブではAIを含め停止し、復帰後は手動再開。経過実時間による収入や市場変化はなし。AI思考待ち・演出待ちのタイマーだけで取引を再実行しない。

## 11. 画面・操作

### 11.1 スマートフォン

上から、戻る・ヘルプ、年齢とラウンド・手番、現金・幸福・次回収支、短い進行ガイド、イベント要約、市場タブ（株式／不動産／融資／幸福）、カード市場、固定の選択詳細と確定操作、資産・負債／ターン終了を配置する。

会社カードには株価、所有者別枚数、所有者の色と記号を付けたカードの重なりを表示。大量のカードは省略表示＋一覧。小さい重なり部分を直接売却対象として操作させず、会社を選ぶと44px程度以上の保有株一覧を開き、原価・売却手取り・損益から対象を選べるようにする。

購入前に支払額、現金前後、価格前後、消費行動枠、次回利息・収支を表示。操作不可理由は「現金が3万円不足」「主行動済み」「担保不足」「売却イベントが必要」など具体化する。

固定バーの高さを確保して盤面末尾を隠さない。詳細パネルは閉じる操作を持ち、背景の誤操作を防ぐ。タップ領域44px程度以上、色に加えて所有者名・記号を併記。

### 11.2 PC・ガイド・演出

PCは左に市場、右に自分の資産・選択詳細・操作、下に対戦者の公開情報。幅320／390／430／768／1280pxと短い横画面を確認する。

初回ガイドと常設ヘルプで目標・操作・行動枠・イベント限定売却・保存・タブ停止を説明。新規ゲームは進行破棄を確認する。効果音は初期OFF。金額と価格の変化を優先し、強い点滅を避ける。OSのモーション軽減に対応し、演出中でも不要な入力待ちを作らない。演出同時数の上限候補は24件（仮値）。演出の乱数は市場乱数から分離する。

### 12.1 主要データ

- Game: schemaVersion、rulesVersion、configSnapshot、seed、rngState、phase、round、turnOrder、activePlayerId、actionUsage、nextId、eventDeck、deckIndex、pendingChoice、settlementId、revision。
- Player: id、name、controller（human/ai）、cash、rehabilitationState。保有枚数等は所有権データから算出。
- Company: id、definitionId、orderedStockIds。価格は株数から算出し、固定の基礎価格を足さない。
- Stock: id、companyId、ownerId（player/NPC）、acquisitionCost、purchasedAt。NPCの原価は損益対象外。
- Property: id、definitionId、ownerId、occupied、acquisitionCost。
- LoanOffer/Contract: id、principal、ratePercent、lenderId、borrowerId、status、startedRound、reservedCash、unpaidAmount。募集と成立済み契約を区別。
- Happiness: id、ownerId（player/NPC）、purchaseOrder。現在価格と勝利点を算出。
- Event: definitionId、対象と結果、処理済みID。未知の未来情報は表示・AIから隠す。
- Settlement: 開始時の契約スナップショット、確定した請求・送金・残債、処理状態。

率は整数比で計算し、現金・元本・受払額は非負整数。IDは一意、株IDは会社1か所だけに属する。取引には資金の相手と根拠を記録し、銀行収支とプレイヤー間送金を区別する。

操作は検証 → 前後比較 → 一括確定。比較画面にはrevisionを持たせ、状態が変われば再計算して再確認。取消・失敗では乱数や行動枠も消費しない。二重タップ・復元による同一操作の二重確定を防止する。

### 12.2 保存と互換性

【確定】操作確定後と精算完了後に自動保存。再読み込み時は続きから／新規を選び、未確定の取引は実行しない。保存失敗や不対応版を表示し、黙って初期化しない。

【提案】保存キーlife-investment-save-v1。乱数状態、設定値、イベント位置、未決選択、精算の確定状態を保存。schemaVersionは構造、rulesVersionはルールを示す。対応済み移行だけ実行し、将来版・不正ID・欠損を拒否。複数タブによる古い状態の上書きをrevision等で防止する。具体方式は実装前に設計確認する。

演出やAI待ちの途中から復帰しても確定済み取引は再実行せず、次の選択状態を表示する。既存ゲームの保存キーへ書き込まない。

## 13. バランス上の懸念

| 懸念 | 検証・調整方針 |
|---|---|
| 幸福先行が常勝 | 幸福先行・株先行・不動産先行・混合を同シード、席順交換で比較 |
| 終盤借入・踏み倒し | 純資産条件、担保、残債、イベント限定不動産換金を組み合わせて検証 |

| NPC株枯渇 | 売りイベント不発率、0万円への到達頻度を測定 |
| ゼロ利息・貸付循環 | 元本と率の整合、貸付債権の担保除外、元本確保を確認 |
| 先手有利 | 先手巡回、イベント受益者、同シード席順交換を比較 |
| 復帰不能の資産整理 | 復帰ラウンド数、残り行動の意味、全員整理時の完走を評価 |
| 後半の幸福一択 | 行動配分の分布を測定。勝敗ルールを無断追加しない |

仮値を使った数値検証・試遊は未実施。バランスが成立したとの主張はしない。

## 16. 初版実装時の確定事項（以前の未決定記述より優先）

ユーザーが実装案を承認したため、U-01～08は以下で解決した。本文の検討経緯・仮値は履歴として残し、この節を優先する。

| ID | 初版の採用仕様 |
|---|---|
| U-01 | 不動産の強制売却なし。家賃を残債返済へ充当 |
| U-02 | 担保は株の順次処分額のみ。幸福条件は購入後現金＋株処分額−元本・残債−次回利息>=0 |
| U-03 | 救済中は株売却と緊急融資1回。元本＋未払利息を残債へ一度だけ移行。株を処分して比例返済し、余りは古い契約順で1万円ずつ。残債0で復帰 |
| U-04 | 提案時に元本確保、借り手の次手番終了で失効・返却。取消しても行動枠を戻さない |

| U-08 | 仮称しあわせ投資録、22～24歳から68～70歳、初回先手はシード抽選、以後巡回 |

金融緩和の10万円・5%は、合意済みの万円切り捨てにより利息0万円となる。上限・担保・契約数・元本返済は免除されない。これは試作上の明示的な調整値であり、端数切り上げへ変更しない。

最終精算は未受諾提案を返却し、元本を一度だけ請求へ移す。株の処分はプレイヤーID順、各社の購入順で行う。不動産は保持し、未完済残債を表示。精算で受け取った金額は同じ精算の支払原資として循環させない。勝敗は幸福のみ。

初版AIは公開情報と合法手だけを使う単純方針。人間と同じ担保・行動・現金条件。未公開山札や未来の乱数結果は評価しない。意図的な貸付や借入は初版AIでは積極使用しないが、人間は全金融機能を操作できる。

保存形式はschemaVersion=1、rulesVersion=1、life-investment-save-v1。確定状態・シード・乱数状態・未決選択・精算状態を保存。別タブ更新は保存トークンで検知して停止する。保存データの手動編集やバージョン不一致は復元拒否。効果音・演出軽減の設定はセッション内のみ。

実装検証の実測結果と残る制約は同フォルダーのREADME.mdおよびTEST_SPECIFICATION.md末尾を参照。
